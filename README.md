# Store Submission Skills

アプリを各種ストアへ出すための、3点セットのスキル集です。準備、素材、提出を別スキルに分け、セットで使います。

対応ストア：Apple App Store（iOS / iPadOS / macOS / watchOS / tvOS / visionOS）、Google Play（Android / Wear OS）、Chrome Web Store、Microsoft Store（Windows）、Firefox Add-ons、Microsoft Edge Add-ons、Samsung Galaxy Store、Amazon Appstore、Steam など。新規ストアは同じ型で追加できます。

## 3つのスキル

| 順 | スキル | 役割 |
| --- | --- | --- |
| 1 | `store_review_readiness`（ストア審査準備） | 公式要件をその場で調べ直し、アカウント・規約・プライバシー・権限・課金・年齢レーティング・技術要件の不足を洗い出し、後続2スキルへの入力リストを作る |
| 2 | `store_listing_pack`（ストア素材パック作成） | アプリ名・紹介文・キーワード・スクリーンショット・アイコン・申告類を、全ストア分まとめて1つのフォルダ（素材パック）に揃え、検証する |
| 3 | `store_submission_ops`（ストア提出実行） | 素材パックをもとに公式APIやブラウザ操作で提出を進め、自動化できない部分は開発者向け手順書に切り分け、リジェクト対応まで追う |

## 補助スキル（3点セットの外側）

| スキル | 役割 |
| --- | --- |
| `store_rejection_checklist`（拒審パターンチェック、公開版） | App Store / Google Play 提出前に、外部で公開されている拒審パターンのデータと対象アプリの実物を照らし合わせ、審査落ちの芽を重大度順に潰す手順。`store_review_readiness` の「審査落ちのパターンを先に潰す」工程の補助として使う。公開版は手順のみで、パターンデータ本体は含まない。データは利用者が出典元（[mjmirza/app-store-compliance](https://github.com/mjmirza/app-store-compliance)）から、出典元のライセンス条件に従って各自取得する |

## 連携のルール（1つ呼べば、依頼の範囲まで進む）

- スキル同士は自動では呼び合わないため、各スキルの「連携と自動継続」の節で連携を定義しています。
- 通し依頼（出す／申請する／公開まで）では、途中のスキルが呼ばれても次のスキルの `SKILL.md` を読んで自動で続行します。止まるのは承認ゲート（提出確定、支払い、規約同意、本人確認書類の送信など）と、利用者や開発者でないと解消できない不足だけです。
- 段階依頼（調べて／素材だけ）では、その段階で止まります。
- 提出実行から始めて前提（審査判定や素材パック）が欠けている場合は、利用者へ差し戻さず、前段のスキルを自分で回してから戻ります。

## このスキル集が守ること

| 原則 | 具体的なルール |
| --- | --- |
| 要件は毎回調べ直す | SDK下限、対象API、手数料、スクリーンショット寸法などの数字を記憶で使わない。公式ドキュメントで確認し、確認日と出典を残す |
| 実態と申告を一致させる | プライバシー申告、権限の理由、説明文、スクリーンショットは実際のアプリの動作に基づく。実画面でないスクリーンショットは使わない |
| 素材は正本1つ | 文案はマスター原稿1本からストア別に文字数だけ変換する。パックは提出先ごとに複製しない |
| 秘密情報を入れない | パスワード、APIキー、署名鍵、デモアカウントの実値はパックやレポートに書かず、保管場所への参照だけを書く |
| 鍵は扱わない | 署名鍵、キーストア、証明書の秘密鍵、APIキー、サービスアカウント鍵など GitHub に上げられないものはスキルの範囲外。生成も保管もせず、手順書に含めて本人が自分の環境で実施する |
| 不可逆な操作で止まる | 提出確定、支払い、規約同意、公開中の削除や価格変更は、利用者の明示承認なしに実行しない |

## インストール

このリポジトリを取得し、使いたいスキルのフォルダをスキルディレクトリへコピーしてください。3点セットは3つとも入れることを推奨します（連携は3つ揃っている前提で書かれています）。補助スキルの `store_rejection_checklist` は任意で追加してください（別途、出典元からのデータ取得が必要です）。

- Codex の場合は通常 `~/.codex/skills/` へコピーします。`SKILL.md` 冒頭の frontmatter（name / description）が登録情報になります。呼び出し名はフォルダ名と同じです。
- Muse の場合は `~/workspace/custom-skills/` へコピーします。Muse 側ではメタデータを `skill.yaml` が担うため、取り込み時に frontmatter を外します。本文の内容は同一に保ちます（運用側の固有名詞表記など、配布形で汎用表記に置き換えた箇所を除く）。

## 使い方

対象アプリと対象ストア、希望する範囲を添えて依頼します。

> `$store_review_readiness` を使って、このアプリを Mac App Store に出す準備をして。不足を洗い出して。

> このアプリを Chrome Web Store に申請して。（通し依頼として、①準備 → ②素材パック → ③提出まで自動で進み、承認ゲートで止まります）

## 状態

- 現在の版は 0.2.0 です。構成と連携ルールは検証済みで、審査準備と素材パックは実案件で回り始めていますが、提出完了まで通した案件はまだありません。実走で詰まった点はスキルへ還元します。
- ストア要件の数字は変わる前提です。references 内の数字は作成時点の目安であり、案件ごとに公式ドキュメントで再確認すること自体がスキルのルールになっています。
