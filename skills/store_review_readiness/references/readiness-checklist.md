# 審査準備チェックリスト（案件用テンプレート）

案件ごとに複製し、状態（済み / 不足 / 不要 / 未確認）と担当を付ける。未確認を済みとして扱わない。

## 1. アカウントと契約

- [ ] 対象ストアの開発者アカウントが有効で、提出権限のあるロールでログインできる
- [ ] 本人確認が完了している（対象ストア分）
- [ ] 必要な規約に同意済み（有料アプリ契約、税務、銀行口座は有料・課金がある場合）
- [ ] アプリの登録枠（App ID、パッケージ名、名前予約）が確保済み
- [ ] 2要素認証とアカウントの連絡先メールが現行のものになっている

## 2. アプリ側の技術要件

- [ ] 最低SDK / 対象API / Manifest版など、提出時期の下限を満たすビルドである
- [ ] 署名が本番用で、鍵の保管場所が記録されている（値は書かない）
- [ ] 使っていない権限を削除した。残した権限は全て機能と対応している
- [ ] 同梱が要る申告ファイル（プライバシーマニフェスト等）が実態と一致している
- [ ] クラッシュなく主要導線が通る（実機または公式の事前検証で確認）
- [ ] アカウント削除導線がある（アカウント作成がある場合）

## 3. 申告の実態合わせ

- [ ] データ棚卸し表が完成している（SDK分を含む）
- [ ] プライバシー申告の下書きが棚卸し表と一致している
- [ ] プライバシーポリシーが公開URLで開け、棚卸しと一致している
- [ ] 権限ごとの理由文が用意できている
- [ ] 年齢レーティング質問への回答が実態と一致している
- [ ] 課金、広告、アフィリエイトの申告材料が揃っている

## 4. 審査の再現性

- [ ] 審査用アカウントが動作する（値は Secure Vault 等への参照のみ記録）
- [ ] 審査用メモの下書きがある（ログイン方法、主要機能への行き方、特殊条件）
- [ ] ハードウェア、地域、時刻など再現できない条件への代替説明がある
- [ ] サーバー側が審査期間中も稼働する見通しがある

## 5. 後続スキルへの入力

- [ ] 素材パック用リストを store_listing_pack へ渡した
- [ ] 提出実行用リスト（ログイン、権限、支払い、本人の判断が要る場面）を store_submission_ops へ渡した
- [ ] 開発者でないと直せない項目に、手順と完了条件を付けた
