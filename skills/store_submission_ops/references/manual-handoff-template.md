# 手順書テンプレート（開発者向け）

スキルだけでは対応できない作業を渡すときに使う。コピーして案件用に埋める。曖昧な依頼文にしない。

```
# 手順書：＜作業名＞（＜アプリ名＞ / ＜ストア名＞）

## 目的と完了条件
- これをすると何が進むか（1文）
- 完了条件：＜画面名 / 表示される値 / 得られるファイル名など、確認できるもの＞
- 期限の目安：＜あれば＞

## 前提
- 必要なアカウントとログイン状態
- 必要なファイルと置き場所（素材パックへの参照）
- 必要な環境（OS、ツール名とバージョン）

## 手順
1. ＜開く場所（URL またはアプリ名と画面名）＞
2. ＜操作＞ → ＜期待される表示＞
3. ...
- 途中で選ぶ値：＜項目名＞ = ＜値＞（理由があれば1行）

## 詰まったら
- 症状：＜よくある表示＞ → 対処：＜戻る場所、やめる判断＞
- 判断に迷う選択肢が出たら、選ばずに止めて知らせる

## 完了したら
- 次をそのまま知らせる：＜完了条件の値、スクリーンショットの有無、表示されたID等＞
- 触ってはいけないもの：＜既存の証明書、公開中の版など、あれば＞

## 注意
- パスワード、鍵、コードはこの手順書にも返信にも書かない
- 支払い、規約同意、提出確定の画面が出たら、押さずに知らせる
- 鍵類（署名鍵、キーストア、証明書の秘密鍵、APIキー、サービスアカウント鍵）の作業はこの手順書の形で渡すのが正規の経路。実施は本人の環境で行い、完了したら「作った事実、保管場所、有効期限」だけを知らせる。鍵そのものやパスワードは送らない
```

## 手順書を書くときのルール

- 1手順書につき1作業にする。複数の作業をまとめない。
- 画面名と項目名は、実際の管理画面の表記に合わせる。不明な場合は不明と書き、推測の画面名を作らない。
- 完了条件がない作業は渡さない。完了を何で確認するかを先に決める。
- 渡した手順書は作業票に記録し、完了報告と実物の照合が終わるまで未完了として追う。
